AI assistants have expanded from completing code to acting on whole software projects as coding agents, carrying out substantial tasks with limited direction from the developer. As those tasks grow, the agent must preserve the project's intent while an increasing body of context competes for the model's finite attention.

Across recent tools and research, two common responses address different parts of this problem. Some record project intent in persistent artefacts before implementation. Others divide work among role-specific agents, each responsible for a bounded part of it. Agentic Project Management (APM) is an open-source framework that combines these two responses: several role-specific coding agents execute work guided by persistent planning documents.\footnote{APM repository: \url{https://github.com/sdi2200262/agentic-project-management}.}

That combination is not unique. APM differs by making coordination user-mediated, aiming to preserve the user's authority over development. Its agents communicate through the user, who can review and intervene as needed before deciding whether to carry each message onward. The effects on cost, process, functional outcome, and developer experience have not been established in use.

We examine these effects through a comparative case study with twelve participants. Each participant completed the same demanding software task twice, once with APM and once with Spec-kit, GitHub's open-source development toolkit for coding agents.\footnote{Spec-kit repository: \url{https://github.com/github/spec-kit}.} Both ran on Claude Code, using Claude Opus 4.7 and Sonnet 4.6, models of different capability and context-window size. The study compared economic, process, functional, and perception outcomes.

Across the cohort, the frameworks carried no firm difference in functional outcome. APM took longer and cost more, but the higher cost was concentrated among participants using Opus; among those using Sonnet, the frameworks cost about the same. Participants nevertheless rated APM more effective and confidence-inspiring.

\section{Summary of Contributions}
\label{sec:introduction-contributions}

Our work makes three contributions:

\begin{enumerate}
    \item It presents APM v1, which brings persistent planning documents, role-specific division of work, and user-mediated coordination into one development framework.
    \item It evaluates APM against GitHub Spec-kit through a controlled within-participant comparison of economic, process, functional, and perception measures.
    \item It provides the reproducible case-study methodology, measures, task environment, and supporting infrastructure required for that comparison.
\end{enumerate}
