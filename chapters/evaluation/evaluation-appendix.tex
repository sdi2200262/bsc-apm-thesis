\section{Evaluation Appendix}
\label{sec:evaluation-appendix}

All case study source code, specifications, and grading infrastructure are available in a single public repository (\texttt{bsc-apm-case-study-task}).\footnote{Repository available at: \url{https://github.com/sdi2200262/bsc-apm-case-study-task}}

\subsection{Repository Organization}

The repository has three top-level directories:

\begin{itemize}
    \item \texttt{task/}:Product Requirements Document, default prompt, and scoring rubric.
    \item \texttt{grader/}:Black-box test suite, data processing pipeline, chat parsers, and SSO mock fixtures.
    \item \texttt{participant-guides/}:LaTeX participant guide for GitHub Copilot.
\end{itemize}

\subsection{Baseline Reproducibility}
\label{sec:baseline}

All tests run against fixed baseline commits:

\begin{itemize}
    \item \texttt{eclass-mcp-server} at commit \texttt{8b4e39c} (main branch)
    \item \texttt{openeclass} at commit \texttt{e8b3329} (Docker image \texttt{openeclass:test})
\end{itemize}

The grading infrastructure applies participant patches against these exact versions. A submission with no patch applied receives the baseline score of 12/100, representing only the existing Python functionality. Environment setup, Docker configuration, and test data seeding are documented in \texttt{grader/SETUP.md}.

\subsection{Test Suite}

The test suite has three categories totaling 100 points:

\begin{itemize}
    \item Python Baseline (12 points):11 test cases covering build, protocol compliance, login, logout, courses, and authentication status.

    \item Python Features (36 points):12 test cases split evenly between the two announcement tools (18 points each), covering error handling, date filtering, output format, and source aggregation.

    \item C Replica (52 points):28 test cases covering compilation, Valgrind memory safety, protocol compliance, and all six tools (login, logout, courses, authstatus, and both announcement tools).
\end{itemize}

Point allocations and test definitions are in \texttt{grader/src/scorer.py}; the scoring rubric is in \texttt{task/SCORING.md}.

\subsection{Submission Workflow}

Each participant completes the task twice in isolated sessions. For each session, the participant creates a dedicated Git branch from the clean \texttt{main} baseline (e.g., \texttt{s1\_apm}), works on the task using the assigned framework, then generates a solution patch as the diff between \texttt{main} and the session branch. After exporting chat logs and saving the patch, the session branch is deleted before the second session begins.

\subsubsection{Submission Format}
\label{sec:submission-format}

Submissions follow a fixed naming convention for automated processing:

\begin{center}
\texttt{\{PID\}\_\{S1|S2\}\_\{platform\}\_\{tool\}\_submission.zip}
\end{center}

The fields are: participant ID (e.g., \texttt{P001}), session number, platform identifier (\texttt{copilot}), and framework identifier (\texttt{apm} or \texttt{spec-kit}).

Each zip contains two items:

\begin{enumerate}
    \item A patch file (\texttt{\_solution.patch}) generated via \texttt{git diff main <branch>}.
    \item A logs folder (\texttt{\_logs/chats/}) containing exported Copilot conversations in JSON format.
\end{enumerate}

The participant guide (\texttt{participant-guide-copilot.tex}) provides full instructions for environment setup, chat export via the VS Code Command Palette, and submission packaging. \placeholder{Model strategy forthcoming.}

\subsection{Data Privacy and Anonymization}
\label{sec:privacy}

All chat exports are anonymized and encrypted during the parsing stage of the grading pipeline.

Each conversation is assigned a unique chat ID computed as the first 16 hexadecimal characters of a SHA256 hash over concatenated user messages. This ID is computed before encryption and preserved in plaintext alongside the following metadata: distinct model IDs, total request count, sanitization timestamp, and original payload size. This metadata enables dataset organization and integrity validation without requiring decryption.

Conversation content is encrypted using an HMAC-SHA256 XOR cipher. A random salt seeds keystream expansion; the serialized chat payload is XOR-encrypted against this keystream and stored in the format \texttt{ENC:<salt>:<ciphertext>}, both Base64-encoded. Decryption with the shared secret produces output bitwise-identical to the original.

\subsection{Grading Pipeline}

The grading pipeline has six stages with manifest-based checkpointing:

\begin{enumerate}
    \item Validation:verifies zip structure and naming format.
    \item Grading:runs the black-box test suite against Python and C implementations.
    \item Parsing:extracts interaction metrics from chat exports and applies the encryption described in Section~\ref{sec:privacy}.
    \item Combination:merges grading results with interaction metrics into unified result files.
    \item Dataset Aggregation:appends processed data to platform-level CSV datasets.
    \item Integrity Validation:verifies dataset consistency against manifest checksums.
\end{enumerate}

Manifests are stored per-platform, recording checksums and timestamps at each stage. Pipeline documentation is in \texttt{grader/PIPELINE.md}.
